# Devices, mixer, and FORCE_* policy

ovVS picks a device per primitive (`gemm`, `topk`, `gather`, pairwise). Algorithms only call `ovvs::prim`.

## Policy (`ovvsResourcesSetPolicy`)

| Policy | Behavior |
|---|---|
| `OVVS_POLICY_AUTO` | Per `docs/hw-split.md`: GEMM/TopK/Gather → CPU oneMKL on this SKU; CAGRA walk → iGPU; range-safe PQ ADC → NPU, otherwise CPU |
| `OVVS_POLICY_FORCE_CPU` | CPU only |
| `OVVS_POLICY_FORCE_NPU` | NPU only. If the NPU does not run the op, the call returns `OVVS_STATUS_DEVICE_UNAVAILABLE`. CPU is **not** reported as an NPU win. |
| `OVVS_POLICY_FORCE_GPU` | GPU only (OpenVINO GPU plugin, or SYCL if `OVVS_WITH_SYCL=ON`). Same unavailable rule. |

`ovvsResourcesLastDevice` is the device that **actually ran** the last primitive. Tests and bakeoff tables compare `last_device` to the forced policy.

`ovvsResourcesSetNpuBusy(1)` is mixer v2: AUTO/HETERO skip NPU, including range-safe PQ ADC, and still complete on GPU/CPU. It is advisory; explicit FORCE_NPU continues to request NPU or fail unavailable.

Large GEMM (`flops >= 1e5×32×768` by default) uses the winner in `tables/<sku>/gemm_large.json` when that file is found (`OVVS_TABLES` or `../../tables` from the binary). On Arrow Lake 265K the measured order is CPU oneMKL, then NPU, then iGPU; AUTO therefore selects CPU.

`ovvsResourcesEnergyUj` returns package microjoules. On Windows the path is the inbox **Intel Processor** driver (`intelppm.sys` / `cpu.inf`) Energy Metering Interface (EMI v2, OEM `Microsoft` / model `PPM`) on the ACPI processor device, channel `RAPL_Package0_PKG`. Units are picowatt-hours → µJ via ×0.0036. Fallback is PDH `\Energy Meter(RAPL_Package0_PKG)\Energy` (same EMI channels), then Intel Power Gadget if installed. Linux uses RAPL sysfs. `GetSystemPowerStatus` is not a package counter. Intel IPF (`ipf_cpu`, PCI `8086:AD03`) and PMT (`IntcPMT`, PCI `8086:AD0D`) are present on this SKU but are DTT/telemetry, not the RAPL EMI publisher. Power Gadget is not required.

## This SKU

Bakeoff JSON lives in `tables/<sku>/`. This lab machine writes `tables/arrow-lake/` (Core Ultra 7 265K). Lunar Lake files are only created if that CPU brand string is actually probed — do not copy Arrow Lake numbers.

Tiny and large GEMM on this SKU both win on **CPU oneMKL** (`cblas_sgemm`): 64×128×32 is 0.006 ms; `1e5×32×768` is **18 ms** vs NPU 45 ms vs GPU 221 ms (`gemm_large.json`). Search-shaped 32×1e5×768 is the same story (CPU 18 vs NPU 36, `gemm_search.json`). NPU DPU is 5.3 ms; the 45 ms wall is Parameter DMA. AUTO GEMM is CPU. Large TopK/Gather stay CPU. CAGRA walk is iGPU. PQ ADC uses NPU only for range-safe tables and otherwise falls back to CPU. See `docs/hw-split.md`.

## CAGRA walk

Search is `prim_graph_walk`. With `OVVS_WITH_SYCL=ON`, the current iGPU checkpoint assigns one work-group per query, cooperatively computes distance, keeps candidates/expansion state in SLM, and uses a traversal-budget-sized global visited hash. Query chunks bound hash allocation near 64 MiB. CAGRA dataset and graph vectors attempt shared-USM allocation so the normal path binds them directly; heap fallback causes explicit per-search device copies. `ovvsResourcesCagraTransferStats` exposes coherent resource-local counters for completed batched walk calls, direct index pointers, upload calls, and upload bytes. Bounded n=4,200/n=2,000 and repeated SIFT1M evidence report direct GPU walks with zero explicit index uploads. These counters do not measure driver-managed shared-memory page migration. Query-content hashing gives CPU and GPU the same deterministic, batch/order-invariant seed stream; it is not yet a graph-aware entry scheme. Exact cached-worst tracking makes full-beam rejection constant-time. Prefix-only publication sorting and a 64-entry local frontier reduce leader work and explicit barriers while preserving filter, visited, scoring, and insertion order. For `search_width > 1`, the first subgroup now selects the exact minimum `(distance, candidate-slot)` cooperatively; width one retains serial-selection semantics. Across three serial-baseline and three candidate SIFT1M processes, cooperative selection improved median QPS by 17.8–29.9% on the three multi-pick rows while recall and a retained old/new bitwise fixture remained exact. At `itopk=64/search_width=2`, CAGRA reaches 0.9609 recall and 3,243.5 QPS versus hnswlib 0.9593 and 6,784.5 QPS, so hnswlib remains 2.09× faster; near 0.989 recall the gap is 3.13×, and the higher-recall batch-one comparator is 42.55× faster. The exact stable one-pass pick was rejected after a negative complete-wall screen. A proposed four-workgroup owner/helper small-batch route is also parked on Arrow Lake: its exact named-kernel capacity gate reported one cooperative workgroup versus four required and launched nothing. Oversized shapes reject explicitly. FORCE_GPU returns `DEVICE_UNAVAILABLE` rather than crossing into the host walk; FORCE_NPU graph search is unavailable because the NPU has no graph-walk implementation. CAGRA-Q remains a host PQ-ADC walk (B10), so both forced accelerator policies reject this host-only walk as unavailable. Adaptive policies may use host walks and report CPU. `ovvsSyclEnabled()` reports whether the compiled SYCL path has a usable GPU at runtime. Evidence: `tables/arrow-lake/cagra-cooperative-pick-v1.md` and `tables/arrow-lake/gpu-root-group-canary-v1.md`.

## NN-Descent and CAGRA build

Through 4,096 rows, NN-Descent uses the exact pairwise/top-k primitive path. Above that threshold, AUTO/GPU_IF_FASTER/HETERO and FORCE_GPU use the B5 sampled iGPU local join for L2, L2-sqrt, inner product, and cosine. The current checkpoint caches distances, tags NEW/OLD neighbors, retains bounded forward/reverse samples, evaluates NEW–NEW and NEW–OLD joins, emits reciprocal proposals, and applies target-owned deterministic merges. Exact changed-edge and pending-NEW counts prevent early convergence while sampled work remains. Input and computed non-finite values fail closed. The output remains a host graph; standalone NN-Descent does not retain a second dataset copy. FORCE_NPU is unavailable, and a present GPU kernel failure does not silently enter the large host loop; OOM and runtime errors retain their statuses. Unsupported adaptive metrics retain the CPU reference path.

`ovvsResourcesCagraBuildStatsV1` exposes a frozen 256-byte, success-only cumulative snapshot for CAGRA construction. It separates dataset copy/finite validation, the selected initializer, optimizer/prune/merge, and persistent graph materialization; records exact logical bytes and initializer-final device; and carries call-local NN-Descent iterations, convergence, allocations, explicit transfers, kernel submissions, total queue submissions, literal waits, and peak algorithm-owned USM. Its inner wall ends before telemetry merge and caller-handle publication, while the benchmark retains a separate complete Python/API build wall. Python can select `nndescent`, `ivf_pq`, or `iterative`; fixed SIFT gates require a fresh instrumented AUTO GPU NN-Descent build and an explicitly matched loaded-library fingerprint.

Bounded sampled exact overlap is 0.9727 at n=4,097/K=8 and 0.8750 at n=16,384/K=16, but both cases exhaust their small iteration budgets without convergence. The original three-run SIFT1M baseline completed in 99.874–100.525 s (100.093 s median), with 90.444 s in the GPU initializer and 9.034 s in host optimize/prune/merge. T13.3 now runs the exact detour-rank prune, capped reverse graph, and deterministic forward/reverse interleave on the iGPU through intermediate degree 64. Three AUTO candidate builds reduced optimizer median wall to 0.641 s and complete build to 91.987 s, while peak process RSS fell from 2,343.2 to 2,269.8 MiB. Dataset-free parent/candidate graph files match exactly at SIFT100K and SIFT1M, recall remains 0.9036, and all initializer lifecycle counters remain unchanged. The candidate initializer still consumes 90.883 s and exhausts six iterations with 5,911,309 changed and 5,949,466 pending-NEW edges, so this is not a convergence claim and does not close T12.5 or K64 scale.

`AUTO`, `GPU_IF_FASTER`, and `HETERO` use the GPU optimizer for supported shapes. Degree-cap or device absence may enter the exact CPU path; a selected GPU runtime or correctness failure does not. `FORCE_GPU` now completes a full NN-Descent CAGRA build only when both GPU stages are supported. Other build algorithms remain unavailable under that policy, `FORCE_CPU` retains the CPU optimizer, and `FORCE_NPU` remains unavailable. ovVS still builds 1.182× slower than unchanged hnswlib in the candidate cohort. Evidence: `tables/arrow-lake/cagra-gpu-optimize-v1.md`, `tables/arrow-lake/cagra-build-v1.md`, and `tables/arrow-lake/cagra-search-v1.md`.

## FP16 / INT8 / FP8 / FP4

`ovvsBruteForceBuildTyped` still converts F16/I8 datasets into an fp32 workspace for search (index storage). **Compute** can be lower-bit: `ovvsGemmEx(..., compute)` keeps host buffers fp32 and runs the MatMul as that type on the device.

- **INT8 (NPU):** NCE MACs are INT8-native (Arrow Lake 3720 TOPS are INT8; FP16 is half-rate). The OpenVINO graph contract is **NNCF Low Precision IR** (FakeQuantize on activations **and** Constant weights), not two runtime `f32` Parameters. Raw `si8` MatMul is rejected. `PERF_COUNT` on this SKU: DPU MatMul is 21 µs for 64³ and 5.3 ms for `1e5×32×768`; SHAVE DMA of the big Parameter is 35 ms **when the C++ path used `set_tensor` on host pointers**. The NPU plugin allocates Level Zero IO at `create_infer_request`; `get_input_tensor`/`get_output_tensor` + `memcpy` is the documented zero-extra-copy feed. `set_tensor(host*)` forces a plugin copy. Baking B as Constant makes DPU faster (2 µs) and **wall slower** (8–24 ms) — Level Zero/UMD, not the MAC array. Scratchpad is 4 MB, so large datasets never stay on-die. Compile hints: `NPU_TURBO`, `PERFORMANCE_HINT=LATENCY`, `NPU_COMPILATION_MODE_PARAMS=optimization-level=2 performance-hint-override=latency`. See `tables/arrow-lake/npu-gemm-dpu-vs-wall.md` and AGENTS.md “NPU contract”. FORCE_NPU still runs FakeQuantize INT8; AUTO low-bit prefers iGPU XMX because that path is a real GEMM.
- **FP16 (iGPU):** Xe Matrix Extensions (XMX/DPAS) do FP16 and INT8. `ovvsGemmEx(..., F16)` AUTO/FORCE_GPU uses oneMKL `sycl::half` GEMM (XMX), then a SYCL-half loop, then OpenVINO GPU.
- **INT8 (iGPU):** oneMKL `int8×int8→float` GEMM (XMX, 2× FP16 issue rate on Xe-core). AUTO I8 prefers this; FORCE_NPU still runs FakeQuantize.
- **FP16 (NPU):** still available via `ovvsGemmEx(..., F16)` FORCE_NPU (`Convert→f16 MatMul`). Not the AUTO large-GEMM default.
- **NPU range safety:** Arrow Lake NPU f32 graph IO can still exhibit FP16-range saturation. GEMM and TopK reject unsafe inputs. Unsafe AUTO PQ ADC stays on CPU. FORCE_NPU can subtract each LUT subspace minimum, scale the remaining total span to 60,000 when the scale is at least 0.5, validate the request-owned output, and restore the per-task bias. Non-finite inputs, wider transforms, and invalid outputs fail without publication.
- **FP8 e4m3 / FP4 e2m1:** probed (`npu_matmul_f8e4m3`, `npu_matmul_f4e2m1`). Arrow Lake 3720 `compile_fail`.

`ovvsResourcesLastComputeDtype` reports the type that actually ran. I8 search ids on `BuildTyped` still match an independent L2 oracle on integer-valued floats. F16 `BuildTyped` ids match an L2 oracle on IEEE-decoded binary16 (atol **2e-2**).

Python `neighbors.*.build/search` accept NumPy arrays and DLPack exporters (`np.from_dlpack` / `__dlpack__`). Search results are NumPy when NumPy is importable.

ScaNN-like indexes train IVF-PQ in anisotropic (per-dim std) space and **re-rank candidates on the original unscaled vectors**.

`ovvsBitsetFromAllowList(n, ids, nids, bitset)` fills a `(n+7)/8` bitset for filtered search. IVF-PQ and IVF-RaBitQ support serialize/deserialize/extend like IVF-Flat. IVF-PQ keeps validated list-major offsets/IDs/codes as derived search state while preserving byte-compatible `IPQ1` v1 serialization; extend publishes canonical and derived state transactionally. Index mutation, serialization, and destruction require exclusive access. Concurrent immutable searches use a distinct `Resources` object per worker.

When `OVVS_WITH_SYCL=ON`, GEMM tries oneMKL GPU then hand SYCL USM (winner cached at first call), then OpenVINO GPU. Device-accessible inputs avoid an extra copy. CAGRA's index-owned vectors use shared USM when allocation succeeds; the host-heap fallback remains correct but copies those buffers for each GPU search. NPU binds host-visible tiles. Hamming and Lp pairwise have a SYCL kernel (FORCE_GPU is honest) and an OpenVINO NPU graph (FORCE_NPU is honest): Hamming is GreaterEqual→LogicalXor→ReduceSum; Lp is Subtract→Abs→Power→ReduceSum→Power. Those lower to Intel ActShave (`eltwise_logical_xor`, `activation_abs`, …) plus DPU ReduceSum. PQ ADC on NPU is OpenVINO Gather+ReduceSum over fixed buckets `{128,256,512,1024,2048}`. Equal-sized query/list chunks are packed into power-of-two-capacity graphs (`Gather` with `batch_dims=1`), and request-owned tensors are reused at depth one. Padded rows have no candidate IDs and are never published. Raw range-safe LUTs execute directly; unsafe AUTO calls use a complete CPU batch, while FORCE_NPU may use the bounded affine transform with atomic validation. Persistent list-major codes remove per-list repacking. FORCE_GPU now performs fused variable-list scan/select and returns only a validated exact-refinement shortlist. Corrected direct-Level-Zero lost refill+execute+consume; NPU+iGPU composition and residual-PQ Q/T lost their joined experimental scopes. Cache/pool and nonzero-NPU work are therefore parked on Arrow Lake. Evidence: `tables/arrow-lake/ivfpq-b3.md` and `tables/arrow-lake/npu-igpu-escape-routes.md`. A raw SHAVE ELF32 is not a firmware load object (`invalid_native_binary`); the compiler embeds kernel `.text` in a graph ELF64. See `compiler/shave/README.md`.

NPU Gather/TopK HostCompile tiles rows (32) and gather indices (128) when a full-shape compile fails.

C++ wrappers cover brute-force, IVF-Flat, IVF-PQ, IVF-RaBitQ, and CAGRA (`include/ovvs/ovvs.hpp`), including serialize/extend. Python `search(..., allow_list=ids)` builds the filter bitset via `ovvsBitsetFromAllowList`.

## HNSW file

`ovvsHnswSerialize` writes the [hnswlib](https://github.com/nmslib/hnswlib) `saveIndex` layout (size_t header, then per-element level-0 links + float data + label). A CAGRA conversion is emitted honestly as a single-layer graph (`maxlevel=0`); it does not invent an HNSW hierarchy. The header keeps hnswlib's conventional `maxM0=2*M` capacity while unused base slots remain zero. Load with `hnswlib.Index(space='l2', dim=D).load_index(path)` when the package is installed, or `ovvsHnswDeserialize`. Stock load/query/save/reload and fully reachable SIFT100K output are validated, but three clean runs lost native hnswlib build and nearest comparable-recall search throughput. B24 is therefore partial: interoperability is complete, acceleration and full SIFT1M recall closeness are not. Evidence: `tables/arrow-lake/hnsw-export.md`.
